## Response Section

#### ข้อดี 
- **อ่านเร็วขึ้น:** query ที่มี `WHERE`, `JOIN`, `ORDER BY` เปลี่ยนจากสแกนทั้งตาราง (O(n)) เป็นค้นหาแบบ B-tree (O(log n)) ยิ่งตารางใหญ่ยิ่งเห็นผล
- **บังคับความไม่ซ้ำ:** Unique index ช่วยกันข้อมูลซ้ำ เช่น email
- **ช่วยเรียงและจัดกลุ่ม:** `ORDER BY` และ `GROUP BY` บนคอลัมน์ที่มี index ไม่ต้องเรียงใหม่

### ข้อจำกัด
- **เขียนช้าลง:** ทุกครั้งที่ `INSERT`, `UPDATE`, `DELETE` ฐานข้อมูลต้องอัปเดต index ด้วย จึงไม่เหมาะกับตารางที่เขียนถี่และอ่านน้อย
- **กินพื้นที่:** index ทุกตัวใช้พื้นที่เพิ่มบนดิสก์และหน่วยความจำ
- **คอลัมน์ที่ค่าซ้ำมาก (selectivity ต่ำ) ช่วยได้น้อย:** เช่น เพศ หรือสถานะที่มีไม่กี่ค่า
- **บาง query ใช้ index ไม่ได้:** เช่น `LIKE '%abc'` (wildcard นำหน้า) หรือครอบฟังก์ชันที่คอลัมน์ `WHERE LOWER(name) = ...`
- **Composite index ต้องเรียงคอลัมน์ให้ถูก:** ใช้ได้ตามหลัก leftmost prefix เช่น index (school, classroom) ใช้ค้นด้วย school ได้ แต่ค้นด้วย classroom อย่างเดียวไม่ได้
- **ตารางเล็กไม่คุ้ม:** การสแกนทั้งตารางอาจเร็วกว่า ฐานข้อมูลอาจเลือกไม่ใช้ index
